# 助手任务闭环更新

本次保持离线规则演示，不添加模型 Key、不接入学校账号、不宣称真实模型智能体评测已完成。

## 校历查询与草稿

- 新增 `get_calendar`，直接查询与校历页面相同的数据库记录，返回学期、周次、考试、假期与原图来源。
- 支持本学期、下学期、第一 / 第二学期、已录入学年的期末、寒暑假、当前周次和主要节日。未知学年不会套用已有校历；节日不推定完整调休。
- 新增 `draft_calendar`，根据首周周一、周数和学期计算草稿及预览链接；不直接写入学校或本机校历。生成窗口收到参数后预填日期、周数和学年，考试 / 假期留待核对填写。
- 链接携带学期和日期，进入校历页面时能对应所查询的学期；校历原图可核对。

## 自习任务闭环

示例：`根据我的课表，找明天下午连续两节空档，推荐至少40人的空教室，并从图书馆导航`。

1. 读取主动分享的课表。没有勾选时提示授权，不把未分享课表当作无课。
2. `find_free_periods` 根据目标日期匹配学期、教学周和星期，只扣除有效课程占用，计算连续窗口。
3. 对每组窗口逐一调用 `find_rooms`；第一组无教室时尝试下一组，而不是把下午 6–10 节一起要求全部空闲。
4. 找到符合容量的教室后才规划路线，并提供教室详情、同一日期节次容量的筛选页、地图入口和来源。
5. 没有空档、没有教室、未知学期均停止相应流程，不编造目的地或导航。

空课表只有明确勾选后才可按“已录入课程无占用”试算；结果仍提醒未录入课程不在检查范围内。上午 / 下午 / 晚上窗口分开，不把中午或晚上拼成连续空档。未指定时长的半天教室查询按连续两节试算，并在答案中说明。

## 范围与隐私

- `share_timetable` 是明确的请求标志；未开启时后端不把随请求附带的课表送给工具或模型。
- 勾选后发送本机课表的必要上下文字段，保留学期字段，按目标学期筛选，避免原来固定第一学期的错误。
- 本次未自动修改课程、预约教室、生成校方通知或保存草稿。生成结果仍由用户在窗口核对保存。
- 离线对话仅补充少量缺参追问，不支持任意多轮推理。模型模式可使用同一工具，仍待真实服务测试。
- 教室状态继续使用演示 / 导入记录；地图仅四条保存的百度查询距离，其余为示意。没有新增真实排课或教师数据。

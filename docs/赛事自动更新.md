# 赛事自动更新

## 范围与触发

现有服务运行期间约每6小时检查一次公开官网来源；应用启动时检查数据库中的最近采集时间，已到期则补检查。后台每5分钟检查是否到期，不是每5分钟抓取学校网站。沿用现有Render服务，不创建付费定时服务。服务器休眠期间不运行；唤醒后恢复检查，因此不承诺全天固定时刻更新。

抓取来源包括学校通知、教务处首页及通知、研究生院两个公开栏目、创新创业学院、校团委首页、统计与数据科学学院和图书馆，共9个入口。当前读取各入口可见的近期链接，最多跟进24篇候选通知，不保证覆盖所有学院或所有历史通知。

## 数据与发布

采集数据保存到现有catalog表的competition_feed分类；采集状态保存为competition_sync/status，不修改个人数据。赛事页面、管理演示页及贝贝工具共用后端赛事清单。随版本提供的资料仍作基础与故障回退，不能把回退标为最新。

标题须包含赛事及通知/报名等动作词，排除获奖、落幕、公示和教师等内容；正文须来自已知文章内容区域，发布时间须在近180天内且不在未来。按学校文章ID或规范化来源URL去重。仅从明确的报名截止/报名时间表述提取日期，不能以作品提交或决赛日期代替；无法可靠识别时显示待核实。部分细节仅在附件或图片中，不自动推测。

公开资料按任务检索时也可使用采集摘要。采集不是人工核验，资格和时分仍以原文为准。自动采集记录显示来源、发布日期和采集日期。

## 来源规则与公众号

访问限制于学校公开HTTPS域名；拒绝外部跳转，限制重定向、响应大小、请求频率并检查robots规则。来源失败时保留已有数据。状态页区分栏目已读取、部分来源不可用和全失败；栏目访问成功不等于所有通知都已识别。

mp.weixin.qq.com/robots.txt禁止自动访问文章页。用户仅有普通读者权限，因此本实现不抓取公众号正文或遍历公众号历史，保留既有原文入口，官网转载的赛事通知可以同步。没有使用登录Cookie、绕过验证、搜狗代理抓取或付费接口。后续如有公众号主体授权接口，可另行接入。

## 接口与运行

GET /api/competitions：基础资料与数据库采集数据合并后的赛事清单。
GET /api/competitions/sync-status：采集时间、来源与数量状态。
POST /api/admin/competitions/refresh：受原ADMIN_TOKEN保护，供维护者手动检查，不开放匿名抓取任务。
COMPETITIONS_SYNC_ENABLED=0：禁用自动任务；测试默认禁用并使用模拟网络。

## 验证

新增测试覆盖报名日期与作品日期分离、冲突日期、旧新闻排除、共享数据源、robots和重定向限制、去重、失败保留及已整理来源日期更新。完整后端98项、前端30项通过，TypeScript与Vite生产构建通过。浏览器用本地模拟接口验证动态列表、手机宽度、状态说明和故障回退。真实官网本地检查9个入口成功；最终线上表现以部署后验证记录为准。

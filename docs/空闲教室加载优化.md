# 空闲教室加载优化

页面按日期读取全日教室快照，根据busy与用户所选节次在页面计算空闲状态。楼栋、容量、类型和房号在本地筛选，不因输入每个字或切换节次重新请求。读取学校数据时仍检查全部楼栋和占用字段，缺失不等于空闲。

## 缓存预热与持久保存

新增GET /api/rooms/snapshot?date=YYYY-MM-DD返回数据库快照及updatedAt、ageSeconds、stale、refreshing和error。接口先返回已有快照，再安排后台刷新，不等待学校的十几秒采集。无缓存时返回warming，页面自动轮询等待首份完整数据，不能当成零间可用。

服务运行期间自动预热今天和明天：今天快照约45秒后尝试刷新，明天约5分钟刷新；循环10秒检查，完整采集期间不会重复发起同日请求。任务可能受学校响应和队列影响，不承诺固定秒数完成。启动后自动补检查，不依赖用户先访问。刷新使用现有学校接口的小批查询和连接复用。

快照保存到现有catalog表的room_snapshot分类，保留最近8个日期，服务重启后仍可读取。后台同时最多2个日期任务，同日合并；失败30秒后才能重试，成功后15秒内不重复启动。新功能沿用现有部署和数据库，不新增付费资源。SCHOOL_ROOMS_PREWARM_ENABLED=0可关闭主动预热；测试环境关闭真实预热。

页面显示学校数据读取时间（北京时间）、快照年龄、选定查询日期和后台刷新状态。60秒及以上或刷新失败时标为需核实的过期快照，教室卡片使用“快照未占用”并去掉实时空闲颜色。旧数据可以查看，但不作为当前空闲保证。HTTP读取失败保留已显示快照并警告；切换日期不沿用旧日期数据。

有后台更新时页面每2秒检查完成状态，平时约15秒读取快照状态。手动更新请求仅安排后台任务，不清空已有缓存；其他日期按首次访问采集。学校异常不覆盖成功快照。服务休眠期间更新暂停，唤醒后先读取保存的快照，再补更新，因此仍有平台唤醒和无缓存日期等待的可能。

## 实时查询边界

贝贝工具及原GET /api/rooms/available仍保持最多60秒的严格缓存，超时或缺失直接报不可用，不使用旧快照冒充实时结果。后台预热也会更新其内存缓存。页面缓存接口与实时工具接口用途明确区分。

## 验证

新增测试覆盖数据库缓存在内存清空后仍可读取、后台阻塞时立即返回旧快照、失败保留及退避、无缓存warming、最多保留8天和无访客时预热今天/明天。浏览器验证后台刷新时先显示缓存、北京时间标签、过期提示、更新完成自动替换、筛选不请求、网络失败保留警告及手机布局。生产构建与前端32项通过，完整后端结果见本次发布验证记录。

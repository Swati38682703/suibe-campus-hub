# 校园食光与手机门户

## 手机门户

手机宽度（600px 及以下）使用顶部校徽与搜索、九宫格服务入口、固定底部导航：首页、助手、食光、课表、我的。其他服务通过首页或顶部菜单访问。桌面保持原有侧栏布局。底部适配设备安全区，照片详情使用原生对话框，支持键盘关闭和焦点约束。

同一 Wi-Fi 手机预览：先停止此前占用 5173/8000 的项目进程，然后在项目根目录运行 `./start.ps1 -Mobile`。电脑访问 `http://127.0.0.1:5173`，手机访问终端打印的电脑 Wi-Fi IPv4 地址对应的 `http://地址:5173`。该模式仅将前端开放到局域网；API 仍通过 Vite 代理访问电脑本地后端。Windows 可能需要允许 Node.js 通过专用网络防火墙。停止方式为启动脚本打印的两个进程 ID。普通 `./start.ps1` 仍仅监听本机。此预览不是公网发布。

## 校园食光

首页与侧栏新增 `/dining`，按餐厅、窗口、菜名/口味查找，支持价格与评分排序、15 元以内筛选、从当前结果随机选餐。

当前为 3 个示例餐厅、6 个示例窗口、12 道示例菜品。名称、位置与价格未经实地核验，不能当作学校真实菜单。维护位置：`backend/app/dining.py`。卡片为表情插画，不是真实菜品照片。

总体评分加口味、分量、性价比、出餐体验四项维度；复用验证码、限次、限流、后台审核、举报、管理凭证撤回流程。邮箱未经验证，仅作为摘要后的限次标识，不代表学校身份认证。提交后在 `/admin` 的点评审核中处理（目标 ID 以 `food:` 开头），仅 `normal` 状态公开并参与评分。没有虚构公开点评或评分。每道菜每邮箱每演示学期限一条。当前示例学期为 2026–2027 第一学期，真实跨学期使用需同步菜单学期。

美食护照：手机调用系统照片选择/拍摄入口（具体由浏览器决定），照片压缩后保存于 IndexedDB；每菜一枚邮票，可更换、移除、下载。解锁首枚邮票、三道菜、三个餐厅徽章。照片不上传、不做菜品识别、位置验证或真实消费证明。清理浏览器网站数据会丢失，换设备不会同步；需下载留存。点评撤回凭证单独存在当前浏览器 localStorage，未实现账号同步。

## 验证

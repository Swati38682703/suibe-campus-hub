# 免费云部署：GitHub + Render + Neon

配置准备于 2026-10-16。仓库尚未上传、云资源尚未创建，不代表已经上线。

## 方案

GitHub 存代码，Render Free Docker Web Service 运行前后端，Neon Free PostgreSQL 保存共享点评和后台数据。构建配置为根目录 `render.yaml` 和 `deploy/Dockerfile`，云入口 `backend.app.cloud:app`。前后端同域，不需要额外跨域设置。手机和电脑均访问 Render 提供的 HTTPS 域名；此时本机不需要开机。课表、收藏、照片集邮依旧只保存在使用者浏览器，不会因部署自动变成账号云同步。

Render Free 无访问 15 分钟后会休眠，下一次请求需等待约一分钟。免费服务有月度用量限制，不能承诺永久在线或固定性能。Neon Free 也有用量限制；以账号控制台和最新政策为准。Render 的免费 PostgreSQL 30 天过期，本方案不使用它，也不把 SQLite 放进临时文件系统。

## 发布步骤

1. 将项目代码放入自己的 GitHub 仓库，建议先设为私有。不要上传 `.env`、`.local-secret`、`campus.db`、`tmp/` 或运行日志，这些已在忽略列表。
2. 在 Neon 创建 Free 项目和数据库。在 Connect 中取得 PostgreSQL 连接串，保留 `sslmode=require` 等连接参数；不要发到聊天或提交到 GitHub。若通过连接器操作，凭证只用于托管环境。
3. Render 使用 GitHub 登录并授权目标仓库。New → Blueprint，选择该仓库，由根目录 `render.yaml` 创建服务，确认计划是 Free。
4. Blueprint 会要求填入 `DATABASE_URL`，填写 Neon 连接串。`APP_SECRET` 与 `ADMIN_TOKEN` 自动随机生成，保持持久且不要频繁更换。数据库 URL 接受 `postgresql://` 并自动选用 psycopg 3。
5. 等待镜像构建和健康检查成功，从 Render 服务页复制 HTTPS 网址。验证首页、直接刷新 `/dining` 与 `/competitions`、`/api/health`，再进行一条测试点评的提交—后台审核—公开—撤回。
6. 后台 `/admin` 凭证在 Render 服务 Environment 中查看，不发到聊天。不启用模型也能使用离线助手；需要模型时单独设置环境变量，模型费用不在免费托管额度中。

不要增加 workers 或多个副本：验证码和当前限流保存在单进程内存中。休眠或重启会使旧验证码失效，需要刷新验证码。启动会初始化示例目录，不自动迁移电脑上的既有数据库；本地历史点评不会自动上传。

## 验证与边界

云入口要求显式 PostgreSQL URL 和 APP_SECRET，防止误用临时 SQLite 导致数据丢失。静态路由支持 SPA 刷新，但缺失 API、资产与敏感文件路径保持 404。数据库连接启用 pre-ping 以处理睡眠后的旧连接。运行后端测试和前端构建后，仍须在获得账号授权后执行真实 PostgreSQL 与云端部署验证。本机没有 Docker CLI，尚未本地构建镜像。

免费平台的国内网络访问速度须上线后用手机实测；如果校园网访问不稳定，再评估其他区域或学校提供的服务器。

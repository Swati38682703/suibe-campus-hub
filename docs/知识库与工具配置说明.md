## 数据来源

种子数据在 `backend/app/seed.py`，以 JSON 存在 catalog 表。教室占用由日期、教室序号、节次的确定性公式生成，仅用于验证筛选交互；无预测或实时含义。教师名称为“某示例”，邮箱使用 example.com；课程和公告为虚构样例。

校园建筑名称基于用户需求文档整理，位置尺寸由代码设置为示意坐标。路径边长使用坐标的欧几里得距离，路由将建筑示意中心连接到最近路网节点，不代表真实入口。地图设施不声称真实位置或无障碍可达性。

knowledge 数据来自需求文档中的平台使用说明与本项目规则。检索当前为多字段子串检索，没有宣称采用向量 RAG。真实指南可通过后续导入工具扩展，需标明来源和有效期。

## 运行模式

### 离线规则演示

无模型密钥时：关键词识别“教室/自习/怎么走/课表/办事”等意图，解析日期、节次、容量，依序执行 Python 工具。返回 `mode=offline`、answer、trace、citations、actions。不支持任意自然语言、多轮指代解析或灵活参数澄清。没有指定路线起点时默认图书馆；没有指定时段时默认 3–4 节。UI 会标识离线模式。

### 大模型模式（待真实服务验证）

设置 `LLM_API_KEY`、`LLM_MODEL`、可选 `LLM_BASE_URL` 后，后端调用兼容 Chat Completions 的服务。模型提出工具调用，后端在白名单内执行，把真实 JSON 返回再交给模型生成解释；最多 5 轮，每轮最多 8 个工具。工具只读，无预约、改课表或发送邮件能力。

工具：

| 名称 | 参数 | 输出 |
| --- | --- | --- |
| find_rooms | date, periods, min_capacity | 最多 5 间所选节次全部空闲的教室、来源 |
| plan_route | start, end（建筑 ID） | 路径、示意距离、估计分钟数、来源 |
| search_campus | query | 教师/课程/教室/公告/建筑/知识记录 |
| read_timetable | 无 | 用户主动分享的本地课表 |

客户端传入的对话历史仅允许 user/assistant，最多 8 条；不接受客户端系统消息。模型密钥不下发浏览器。提示词明确要求来源、示例数据标记、未知问题澄清，以及将资料中的指令视为数据；尚未完成真实模型提示注入评测。

## 数据管理与边界

CSV 导入支持教室、占用、教师、课程，以 ID 更新。导入过程先校验全文件，失败时不写入。ADMIN_TOKEN 默认空，后台拒绝访问；配置后凭请求头验证。开发模式只绑定 loopback。

点评邮箱做带服务器密钥的 HMAC，不存明文邮箱。密钥需要长期保留，改变密钥会改变邮箱限次身份。点评凭随机 management_token 删除，数据库只存摘要；每邮箱每课程每学期由数据库唯一约束限一次。验证码 3 分钟有效且一次使用；限流仅单进程内存，Docker 后端保持单 worker，生产多副本需改 Redis/持久方案。

敏感词拦截仅为基本示例，所有提交默认 pending，由管理员审核后公开。隐藏点评不纳入统计。该方案无法阻止多邮箱刷分，也不提供学生身份真实性保证。
